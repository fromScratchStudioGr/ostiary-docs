The local key service is built into Ostiary, so it needs nothing else to run. It is what the [quick start](/docs/getting-started/quick-start) uses.

<Callout type="warn">
Use the local key service only for trying Ostiary out. Its master key is a setting given to Ostiary itself, so anyone who can read Ostiary's settings can unlock every provider key. It also keeps no record of who unlocked what, and its master key cannot be rotated. For real use, choose [Google Cloud KMS](/docs/key-management/google-cloud-kms) or [OpenBao](/docs/key-management/openbao).
</Callout>

## Setting it up

The local key service is the default, so `KMS_PROVIDER` can stay unset. It needs one setting, `LOCAL_KMS_MASTER_KEY`: 32 random bytes, written in base64.

Create it in the `.env` file next to `docker-compose.yml`:

```bash tab="bash"
echo "LOCAL_KMS_MASTER_KEY=$(openssl rand -base64 32)" > .env
```

```bat tab="cmd"
powershell -NoProfile -Command "$b = New-Object byte[] 32; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); 'LOCAL_KMS_MASTER_KEY=' + [Convert]::ToBase64String($b) | Out-File -Encoding ascii .env"
```

```powershell tab="PowerShell"
$b = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
'LOCAL_KMS_MASTER_KEY=' + [Convert]::ToBase64String($b) | Out-File -Encoding ascii .env
```

These commands replace the whole `.env` file. If you already have one, add the line to it instead.

If the setting is missing, or is not 32 bytes of base64, the gateway and the admin API do not start.

## Keep the master key

Keep the master key for as long as you use Ostiary. If you lose it or change it, Ostiary can no longer read the provider keys it has stored, and you have to add them again.
